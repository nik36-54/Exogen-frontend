# EXOGEN — PROMPT 2

## Build the Core Intelligence Flow: Signal → Contract → Canonical Event → Market Consensus → Risk → JPMorgan Exposure → Risk Score → Dollar Impact

You have already completed **Prompt 1**, which established the Exogen design system, application shell, navigation, overview dashboard, reusable components, and visual language.

Now build the **most important product experience in Exogen**.

Do NOT redesign the existing application shell or replace the design system.

Instead, extend the existing frontend and build the core intelligence workflow:

**EXTERNAL SIGNAL**
↓
**MARKET CONTRACT**
↓
**CANONICAL EVENT**
↓
**MARKET CONSENSUS**
↓
**RISK**
↓
**JPMORGAN EXPOSURE**
↓
**RISK SCORE**
↓
**POTENTIAL DOLLAR IMPACT**

This should feel like a serious institutional intelligence product—not a dashboard with cards.

The user should be able to start with:

> “Something changed in the external world.”

and progressively understand:

> “What changed → What exactly is happening → How certain are we → Why does it matter → What is exposed → How significant is the risk → How much money could be affected?”

---

# 1. CORE PRODUCT EXPERIENCE

Build an interactive **Signal Intelligence Detail Experience**.

When a user clicks a signal from the Overview or Signals page, open:

`/signals/:signalId`

The page should feel like entering an intelligence investigation.

The experience should have a persistent top-level context:

**Signal → Event → Risk → Exposure → Impact**

Use a horizontal contextual breadcrumb / intelligence pipeline near the top:

`Signal` → `Contract` → `Canonical Event` → `Consensus` → `Risk` → `Exposure` → `Impact`

Each stage should be clickable.

The current stage should be visually emphasized with the Exogen lime accent.

The user must always understand where they are in the chain.

# 37. THE "WOW" STANDARD

The finished experience should make a user understand Exogen's value within approximately **30 seconds**.

A user should be able to answer:

### What happened?

A prediction-market probability changed.

### What exactly is the event?

Exogen normalized it into a canonical event.

### How confident are we?

Multiple venues agree and the data quality is strong.

### Why does it matter?

The event maps to a business risk.

### What is exposed?

Specific JPMorgan business units.

### How significant is it?

Risk Score.

### How much could it matter financially?

Potential Dollar Impact.

### Can I verify it?

Yes—through provenance and calculation details.

That is the core Exogen experience.

# 38. IMPORTANT PRODUCT PRINCIPLE

Do not build this as:

**"A dashboard showing prediction markets."**

Build it as:

**"An intelligence system that translates external probability signals into business consequences."**

The prediction market is the INPUT.

The business impact is the OUTPUT.

The entire UI should reinforce that relationship.

The strongest visual hierarchy should therefore be:

**$ IMPACT**
↓
**RISK**
↓
**EXPOSURE**
↓
**PROBABILITY**
↓
**EVENT**
↓
**SOURCE**

Consider Prompt 2 complete only when:

1. Clicking a signal opens a complete intelligence detail experience.
2. The user can follow Signal → Contract → Canonical Event → Consensus → Risk → Exposure → Risk Score → Dollar Impact.
3. Every stage is visually connected.
4. Canonical event matching is clearly explained.
5. Multiple contracts can map into one canonical event.
6. Market consensus is clearly explained.
7. Cross-venue disagreement is visible.
8. Risk classification is visible.
9. JPMorgan exposure is visible by business unit.
10. Direct vs indirect transmission is represented.
11. Risk score has a transparent breakdown.
12. Dollar impact has scenario analysis.
13. Every major number has a "Why?" explanation.
14. Provenance is accessible.
15. Technical details are available without overwhelming the default UI.
16. The entire flow uses structured mock data rather than scattered hardcoded JSX.
17. The architecture is ready for future API integration.
18. At least 3 scenarios can be demonstrated.
19. Loading and error states exist.
20. The final result feels like institutional risk intelligence software—not a prediction-market frontend.
